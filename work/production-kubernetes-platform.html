Production Kubernetes: diagnose, rebuild, right-size and monitor

For a US crypto-wallet company, I found out why production pods kept getting evicted, built a new hardened production cluster next to the old one, moved development to a much cheaper single-node cluster, and replaced the monitoring with dashboards and alerts generated as code.

Role: DevOps EngineerAWS · EKS · KubernetesJenkins · HelmGrafana · CloudWatch

The context

A busy production cluster that kept tripping over itself

The company runs its wallet backend, API services, scheduled jobs and back-office tools on Amazon EKS, with Jenkins building and deploying them through Helm. Development and production had grown up together, and a scheduled-jobs service in production was being evicted every day.

My job was to find the real causes without risking production, give the team a safe plan, and build the better platform in parallel so nothing had to change in place.

What I did

My work, step by step

Root-cause analysis and a safe remediation plan

Investigated the cluster with read-only commands only, so every finding could be reproduced by the team.

  • Traced the daily evictions to a combination of causes: workloads pinned to a single node, no resource requests or limits, a memory limit set too close to node size, an outdated cluster autoscaler and a production job using development values.
  • Reviewed GitOps, quotas, disruption budgets, storage classes, Kubernetes version support and leftover resources.
  • Wrote a phased plan with effort, risk, rollback and exit criteria for every phase.
  • Prepared a security and delivery roadmap: OIDC-based CI, a secrets manager, code, dependency, image and IaC scanning, and immutable, promoted builds.

New hardened production cluster, built in parallel

Built a new EKS cluster next to the old one so production could move over without in-place changes.

  • Private API endpoint with modern access entries, nodes across two availability zones on the current Amazon Linux.
  • IMDSv2 required on every node and encrypted gp3 volumes.
  • Dedicated load balancer with TLS 1.3, managed by the AWS Load Balancer Controller through an IAM role for service accounts.
  • Workloads deployed and validated on separate test hostnames, including database reachability from inside a pod, without touching any live DNS record.

A much cheaper development environment

Moved development off the shared cluster onto a single-node Kubernetes host on EC2, running in parallel until cutover.

  • Private host behind its own load balancer with a wildcard certificate; network rules allow only the load balancer, the CI server and VPN users.
  • An instance role with exactly two managed policies replaced static keys; a systemd timer refreshes the registry pull secret every 8 hours.
  • The Kubernetes API is reachable only from CI, and CI uses a service account limited to one namespace (denials tested).
  • A new Jenkins pipeline with a guard stage that can never deploy to the production cluster, immutable build tags, Helm deploys and rollout checks.
  • Helm values linted and rendered against the real chart, which caught a broken ingress before it shipped. Cutover runbook: one hostname at a time, with a DNS-only rollback.

Monitoring platform, generated as code

Replaced hand-built monitoring with a managed, reproducible setup, after backing up every existing dashboard and alert.

  • Measured log volume first to estimate cost before building anything.
  • Managed Grafana with single sign-on and group-based roles.
  • Container Insights for the new cluster, the CloudWatch agent rolled out to all EC2 servers through SSM, plus databases, queues, API gateway, load balancers and NAT.
  • Two small Lambdas: a multi-region server and database inventory, and load-balancer log parsing for 5xx errors.
  • Dashboards and alert rules generated by Python scripts with an automatic panel checker; thresholds set from 7 days of real data.
  • A backup path from CloudWatch alarms to chat so alerts still arrive if Grafana is down. Every step additive, with an undo section.
