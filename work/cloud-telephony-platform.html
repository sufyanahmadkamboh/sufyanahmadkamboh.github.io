Employer projectLastingSales (HadiTelecom) · 2021 – 2024

Cloud PBX and sales CRM: two products, one platform, kept running

LastingSales runs two products: its sales CRM, and, under its telecom brand HadiTelecom, the Zong vPBX cloud phone system it delivers as a vendor to Zong (China Mobile Pakistan). I owned the infrastructure of both: the VoIP platform and its Kubernetes portal, the CRM's microservices on Amazon EKS, the link that feeds call data from the phone system into the CRM, CI/CD, monitoring and backups.

The context

One company, two products

LastingSales is the parent company. Its telecom side, branded HadiTelecom, is a vendor to Zong (China Mobile Pakistan) and runs the Zong vPBX platform. Its software side builds the LastingSales CRM.

Zong vPBX gives businesses a virtual phone system in the cloud: numbers, extensions, IVR menus, call queues, voicemail, call recording, surveys and a self-service portal, with reports for every call. It served 4,000+ business clients and processed 6M+ calls per month.

LastingSales CRM is a sales CRM for service businesses: lead capture from ads and web forms, lead distribution, follow-up tracking, call recordings, team analytics and a mobile app. Many clients used both products, so their calls had to show up in the CRM without manual work.

The challenges

What had to be solved

📞 Calls can't waitVoice is real-time: a server restart in the wrong place drops live calls for many companies at once.
🗃️ Call records pile upMillions of call records a month slowed down reports and the databases behind them.
🔄 Legacy deploymentsThe portal ran on hand-managed servers that were slow and risky to update.
🛡️ Carrier security standardsThe operator's security test had findings that had to be fixed on the public web apps.
🔗 Two products, one customerClients using the phone system and the CRM needed their call data in the CRM automatically.
📈 A growing CRMThe CRM's services had to deploy, scale and be monitored independently, with reliable backups.

What I did

My work, layer by layer

📞

VoIP platform operations

Kept the voice layer running for thousands of business tenants.

  • Ran the SIP proxy layer (Kamailio) in front of multiple Asterisk media servers, including Asterisk running in containers.
  • Owned multi-tenant dialplan changes: IVR, queues, time conditions, voicemail, caller-ID masking, call-back and feedback surveys, recording with automatic conversion to MP3.
  • Supervised the team developing custom SIP applications and dialplans for enterprise call routing.
  • Built concurrent-call graphs from call records to plan capacity.

☸️

Kubernetes and high availability for the portal

  • Moved the customer portal from hand-managed servers into containers on a high-availability MicroK8s cluster with MetalLB.
  • Put HAProxy in front for TLS termination, health checks and load balancing, with Keepalived holding a floating IP so a failed proxy is replaced automatically.
  • Built a private container registry with TLS for the platform's images.
  • Jenkins pipelines written in Groovy that build Docker images on every push to the development branch and deploy them, for zero-downtime releases.

🗃️

Call-data lifecycle, storage and backups

  • Wrote archiving scripts that move call records older than 90 days to an archive database, day by day, with error handling, keeping reports fast.
  • Database backup and restore scripts; replicated MySQL and synced files between voice nodes.
  • Network storage with redundant disk pools and failover network links for recordings.

🛡️

Network and security

  • Designed the network with separate VLANs for signalling, media and management on layer-3 switches, behind a firewall with VPN-only admin access.
  • Fixed findings from the operator's web-application security test: server upgrades, security headers (HSTS, CSP, frame protection), debug mode off and stricter upload limits.
  • Wrote the staff off-boarding and credential-rotation process.
  • Nagios checks for the hosts and services of the voice platform.

LastingSales CRM on Amazon EKS

Managed the CRM's AWS infrastructure and moved it onto Kubernetes as multi-container microservices.

  • Deployed the web app, core API and supporting microservices as separate containers on Amazon EKS, so each one deploys and scales on its own.
  • Jenkins pipelines written in Groovy to build, push and deploy every service.
  • Prometheus and Grafana for cluster and service monitoring, with dashboards and alerts.
  • Wrote the backup scripts for the CRM's data, plus restore steps.
  • Ansible playbooks for server bootstrap and automated wildcard TLS certificate renewal through DNS validation.
