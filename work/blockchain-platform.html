Layer-1 blockchain platform: environments, security-ready network and observability

For a client building its own EVM-compatible blockchain, I ran the cloud infrastructure behind the chain and its apps: isolated network environments for every stage, a private network design ready for a security test, monitoring, cost tracking and a backup of all source code.

Role: DevOps EngineerAWS · EC2 · VPCPrometheus · Grafana · LokiJenkins · PM2 · Nginx
Confidential client work. Network names, repositories, addresses, regions and internal designs are left out on purpose. This page describes the engineering approach and what I did.
The context

A new blockchain needs more than one network

The platform is a Layer-1 chain with validator and bootstrap nodes, a block indexer, a block explorer, a wallet and apps built on top. Developers needed separate networks to test changes without breaking each other, and the client needed a public test network and an environment that independent security testers could attack.

The challenges

What had to be solved

What I did

My work, layer by layer

Five isolated chain environments on AWS

Ran separate networks for the public test chain, development, two experimental chains and security testing.

  • Each environment split into a node instance (validator and bootstrap) and an app instance (explorer, indexer and apps).
  • Chain nodes on ARM Graviton instances for better price-performance, sized up for heavier development networks when needed.
  • Managed PostgreSQL for the block indexer.
  • Services run as managed processes under PM2 behind Nginx.
Amazon EC2GravitonAmazon RDSPM2Nginx

A network ready for a security test

Rebuilt the security-test environment so nothing sensitive had a public address.

  • Custom VPC across two availability zones with public and private subnets and separate route tables.
  • Nodes and apps moved to private subnets; outbound traffic through a NAT gateway only.
  • Explorer, indexer and node RPC published through Application Load Balancers.
  • A single bastion host as the only way to reach servers over SSH.
AWS VPCNAT gatewayApplication Load BalancerBastion host

Observability and health checks

  • A dedicated observability server with Prometheus for metrics, Grafana for dashboards and Loki for logs.
  • Wrote a small Node.js server-health API, protected by an API key, that reports CPU, memory, disk, Nginx status and the health of every PM2 process (chain, indexer, explorer and apps).
PrometheusGrafanaLokiNode.js

Cost tracking, CI and source-code backup

  • Produced monthly cost breakdowns per environment so the client could decide what to keep running.
  • Hosted Jenkins for builds and deployments.
  • Wrote a script that mirrors every repository in the organisation, public and private, with logging and an update mode, as an independent disaster-recovery copy of the code.
